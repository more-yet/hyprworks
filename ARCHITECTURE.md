# Runtime ownership

Each `Invocation` owns one configuration execution. Its state is shared by the
operations that need it and destroyed on close/reload. It is not a process-global
singleton: embedding two invocations must not silently share Lua or Wayland state.

```text
InvocationState
├── Lua, wake descriptor, reusable wait vector
├── timers, processes, watches and native desktop integrations
└── Gui
    ├── Wayland connection, registry, outputs, seats and protocol globals
    ├── xkb context/compose table and Pango font map/context
    ├── surfaces and their element arrays
    ├── reusable presentation buffers and clipboard transfers
    └── one image worker, bounded queue and icon-theme cache
```

The GUI uses stock Wayland, Cairo, Pango, xkbcommon, libpng and librsvg APIs.
Protocol bindings are generated by wayland-scanner. No toolkit backend or
patched dependency is part of the build.

## Execution

`Invocation::run` owns the `ppoll` loop. The wait vector is reused across turns.
Native integrations supply descriptors/deadlines and consume readiness directly.
The executable handles termination/reload signals with lock-free pending bits
and a nonblocking self-pipe. Signals remain unblocked so desktop applications and
actions launched through GIO inherit normal signal handling. Pending bits retain
requests when the wake pipe fills; termination takes priority over reload.
Lua's instruction hook also checks them so a busy script remains interruptible.
The runner's handler state and pipe live until process exit, across reloads.
Embedders retain ownership of signal handling and can supply a borrowed
`SignalSource` or use cross-thread wake/request operations.

Wayland preparation/read/cancellation is private to this loop. Every successful
`prepare_read` is paired with `read_events` or `cancel_read`, including interrupted
waits and shutdown. Flush backpressure enables `POLLOUT`.

Native callbacks retain bounded state or events; they do not invoke Lua.
Readiness is consumed before Lua callbacks can close/reuse descriptors.
GUI input packets are delivered in order, with interaction callbacks between
packets. Hit testing resolves dirty layout before using it. Other integration
sources have no synthetic global event ordering.

The GUI queue permits 256 input packets. Clipboard I/O processes at most 64 KiB
per transfer per turn. Exhaustion that would lose ordered input fails the runtime.
Continuous presentation is paced by compositor frame callbacks.

## State and lifetime

A surface owns its role, element array, focus and editing state. Elements are
plain per-kind data with parent/subtree indices. Layout and rendering consume
that same array; there is no mirrored toolkit tree.

Lua handles contain surface identity and, for elements, tree revision/index.
Surface IDs are not reused during an invocation. Closed slots are reusable after
the next safe reclamation step. Replacing a tree invalidates its old element
handles, resets focus/scroll state and releases callback references.
Subtree replacement also invalidates handles, but retains surviving element
resources and remaps their logical focus. Parsing and validation finish before
moving any live elements; press ownership and composition reset at the commit.

Parsing builds temporary owned content inside protected Lua calls. A complete
validated tree is swapped into place atomically. Setters stage one element in
the same way. Failed parsing leaves existing state intact.

Close immediately prevents new operations and marks popup descendants closed.
Protocol destruction and reclamation occur after callback delivery. Userdata
does not own native resources and has no resource-destroying GC finalizer.
Explicit close and runtime teardown determine their lifetime.

Lua allocation may still execute user finalizers. Operations resolve handles
again after marshalling and before committing. No element reference may be used
after a Lua call that can replace its tree. Protected calls keep C++ ownership
outside frames that Lua errors can bypass using `longjmp`.

Uncaught callback errors stop the invocation. Operational API failures return
`nil, error`; malformed Lua arguments raise errors. Programmatic setters never
generate interaction callbacks.

## Rendering and presentation

Layout computes intrinsic dimensions, measures under available width, then
arranges boxes. Rows/columns share remaining space through explicit growth
weights. Containers clip; scroll containers maintain one offset on their chosen axis.
Pango handles text measurement, shaping, logical attributes and cursor geometry.
Element updates retain their Pango layout when the font is unchanged.

Cairo paints directly into owned ARGB `wl_shm` buffers. Raw images are converted
to premultiplied pixels without encoding. Logical geometry is separate from
buffer dimensions; fractional scale uses a viewport and rounded pixel extents.

Only dirty, configured surfaces with a frame opportunity render. Each render
fully repaints its chosen buffer, so correctness does not depend on buffer age.
Buffers remain immutable while submitted. Release permits reuse; a frame callback
permits presentation. Resized/closed surfaces can leave busy retired buffers,
which remain accounted until released.

Presentation storage is capped at 256 MiB, with at most three buffers per surface
including retired sizes and at most 128 MiB per buffer. Three busy buffers wait
for a release. Global exhaustion reclaims idle buffers and otherwise reports an
error; there is no resize allocation backlog or indefinite memory-budget stall.

## Input and independent work

Seats own keyboard maps/state, compose handling, clipboard offers and text-input
objects. Protocol listeners capture input with its target/serial. Surface focus
and selection are native state; Lua controls shell-level interaction policy.
IME edits are applied as transactions, with stale tree targets rejected.
Clipboard paste also checks the target's editing revision.
Focus is shared within a surface. Its active press records both seat and
pointer/touch source; unrelated motion, release and cancellation are ignored.
Preedit cancellation is tied to its originating seat and tree. Painting and
IME cursor rectangles use the same caret geometry and horizontal scroll.
Surrounding-text reports include the entire selection within the protocol's
message bound. Larger selections temporarily omit surrounding-text support.
Password inputs mask display text, reject copy/cut and disable IME exchange.
Surface input callbacks can consume keys; pointer cancellation remains native.

Clipboard I/O is nonblocking on Hyprworks-owned endpoints; a receiving pipe's
write end retains blocking semantics for the source application. Transfers are
limited to 1 MiB each, sixteen concurrent transfers and five seconds. Writes
contain SIGPIPE locally without changing the embedding application's
process-wide signal policy.

Image requests own their source. One worker decodes PNG/SVG or converts raw
pixels; it never invokes Lua or touches Wayland. Release/acquire publication
makes completed pixels/errors visible to the owning thread. The queue holds at
most 32 jobs; further live requests remain on their elements until capacity is
available. Superseded queued work is discarded. Both completion and discard
wake the event loop so deferred requests can use the released capacity.
Source paths, icon names and themes stay immutable during decoding and count
toward the tree's string limit.

Image input is limited to 8 MiB, dimensions to 4096 and accounted input/pixel
storage to 128 MiB. Decoder-internal allocations are not a hard process memory
limit. An active library decode is not forcibly interrupted; shutdown joins it.

## Close and reload

Stop accepting work, suppress callbacks, cancel queued work and join the image
worker. Destroy popup roles before parents; release integrations, buffers and
protocol objects, then disconnect. Release Lua roots and close Lua while runtime
handle checks still exist. Finally destroy state.

A reload constructs a new invocation. It deliberately reconnects integrations
and remaps surfaces rather than keeping a second configuration alive for rollback.

## Source boundaries and verification

- `src/lua/invocation.cpp`: configuration ownership and event loop.
- `src/lua/gui/gui.cpp`: protocol lifecycle, tree, input, rendering and Lua GUI API.
- `src/lua/gui/images.cpp`: the independently executing image worker.
- `src/lua/gui/icons.cpp`: bounded icon-theme lookup, used by that worker.
- `src/native/`: existing independently owned desktop protocol implementations.

These are concrete execution/resource boundaries, not pluggable backend layers.
The public GUI API and supported primitives are documented in `README.md`.

`tests/invocation_core.cpp` checks busy-script interruption, wake-pipe saturation,
termination precedence, cross-thread reload requests and callback failure cleanup.
`tests/gui_core.cpp` exercises editing, stale targets, callback-driven replacement
and close, failed-creation cleanup, pixel ownership and broken-pipe handling.
Its clipboard check passes the actual receiving descriptor through Wayland's
FD transport and transfers 1 MiB from a blocking writer through a 4 KiB pipe.
Its `image-worker` check isolates queue capacity, cancellation, publication and
shutdown from Pango's independently threaded font initialization.
`tests/gui.lua` exercises configured windows/layers, popups, source cancellation,
tree replacement and slot reuse against a compositor.

An offscreen measurement on a Ryzen 9 9900X, with optimized GUI code, 200 buttons,
one Lua text update per frame and full layout/painting, averaged 1.93 ms at
1920×1080 and 3.40 ms at 3840×2160 (500 frames after 50 warmup frames; p95
1.95/3.71 ms). This excludes compositor presentation and is not a frame-rate
guarantee.

Live compositor lifecycle, keyboard editing and a text-input-v3/input-method-v2
protocol fixture pass. Full IME-engine interoperability, simultaneous hardware
multi-seat interaction and end-to-end fullscreen animation still need coverage.
